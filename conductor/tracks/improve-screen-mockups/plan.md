The registration deposit is credited once (`registrationDeposits.creditedLotId`). Buyer API in `convex/lotPayments.ts` (`getMyWonLots`, `claimLotPaid`, `getMyCollectionDetails`, `getMyPaymentSummary`, `updateMyCollectionAddress`, `getMyCollectionAddress`), admin API in `convex/admin/lotPayments.ts` (`listLotPayments`, `confirmLotPayment`). Deviations from the brief: `createLotPayment(ctx, lot, winnerId, bid, at)` takes the hammer price explicitly (the lot snapshot is stale on the accept path); `notifyUser` and `formatNotificationRand` moved to `convex/lib/notify.ts` (re-exported from `auctions/internal`) to avoid an import cycle; a sold lot with a payment record is protected from `voidBid`, status changes out of `sold`, `syncLotWinners` and a deposit refund of the credited deposit (reassigning the winner after a sale is a follow-up); demo bidders get no payment row. No backfill: lots sold before this shipped have no payment row, and `wbtImport` / `wbtDemo` showcase lots never get one.

M2 done as: `ensureWatching(ctx, userId, lotId)` (`convex/lib/watching.ts`) is called by `placeBidHandler` after the bid and activity log succeed (so a throwing bid never watches) and by the watch toggle. Deposit refund: `refund_requested` + `refundRequestedAt`; `requestDepositRefund` / `cancelDepositRefundRequest` in `convex/registration.ts`, guards in `convex/lib/depositRefund.ts` (`refundableRemainder`, `loadUnpaidPayments` shared with `getMyPaymentSummary`, `isLeadingOpenLot` over the newest 200 non-voided bids via `by_bidder_timestamp`). Registration submissions do not notify admins in-app (they only show in the queue), so the refund request writes an in-app notice to up to 20 admins. Asking again while already `refund_requested` succeeds quietly. `getMyBidsOverview` lives in `convex/auctions/queries/bids.ts` (barrel: `api.auctions.getMyBidsOverview`); `nextMinBid` is `currentPrice` for a lot with no bids, else `currentPrice + increment` (the bid path's rule, not `startingPrice`; `lib/nextMinBid.ts`, and `getMinIncrement` now takes a `Pick`); the overview's rows always have a bid, so it always adds the increment. Won count = the caller's `lotPayments` rows + sold lots they won that have no payment row, found only among the lots read (there is no `lots.by_winner` index), so a very old legacy win outside the 200-lot window is not counted. `counts.bidding` and `counts.lost` are counted within those caps (lost before its 50-row cap); Watching is capped at 500. Switches: `pushSwitchAllows` / `pushToUser` / `pushLotsWon` in `convex/lib/pushToUser.ts`; pay-by reminder in `convex/lib/payByReminders.ts` (only payments whose deadline is still ahead and within 24 h; overdue ones are not reminded; a claimed payment is left alone) behind cron job `send_payment_reminders`. Review round (coordinator): the refund guard also counts a leading `under_consideration` lot (request and admin refund); `refundableRemainder` is shared with `markDepositRefunded` and treats a credited lot without an amount as fully used; a payment covered in full by the deposit is confirmed automatically (`applyDepositCredit`, `notifyPaymentConfirmed`); new eligibility kind `refund_requested`; the reminder index is `by_status_and_reminderSentAt_and_payBy`; the Won count reads at most 500 payments; `/admin/deposits` already has the refund tab and action (done here, not in M7). Owner decision: a credited deposit still lets the buyer bid. A lot relisted after going unsold still shows the buyer's old bids in Bidding (as in `getMyBids`). Deviations from the brief: `getMyRegistration` also returns `refundableAmount`, and the admin deposit row and review validators return `refundRequestedAt` (data for M5 and M7).

- Done as: `lotNumber` comes from a monotonic per-auction counter (`counters` row `lotNumber:<auctionId>`, `total` = last number issued) so a number is never reused within a sale; unassign and unsold settlement clear it and nothing is re-packed. `backfillLotNumbers` walks `lots` in `_creationTime` order, numbers assigned/sold/unsold lots that still have an `auctionId` via the same counter, skips already-numbered lots (raising the counter to cover them) and reschedules itself in batches of 100.
